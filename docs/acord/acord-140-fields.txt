# ACORD 140 (Property Section) — form field inventory
#
# Read off the agency's own uploaded template with Settings → Inspect fields.
# Same status as the 125's inventory beside it: a snapshot of this agency's
# template, not a standard, and the only authority on what the mapping may name.
#
# ## The shape, which is not what W5 assumed
#
# **Two buildings per PDF.** There are two complete building blocks. Their
# suffixes are NOT a clean _A/_B split — that is the trap in this file:
#
#   | Section                          | Block 1   | Block 2   |
#   |----------------------------------|-----------|-----------|
#   | Location / building identifiers  | _A        | _B        |
#   | Construction, protection, heat   | _A        | _B        |
#   | Subject-of-insurance rows (5 ea.) | _A.._E    | _G.._K    |
#   | Premises remark text             | _A        | _C        |
#   | Heating-boiler-elsewhere code    | _A, _B    | _C, _D    |
#
# There is no `_F` subject-of-insurance row. Interpolating one block letter
# across a whole block would produce four wrong names in block 2 and one in
# block 1, which is why the mapping carries an explicit table per block.
#
# So an account with N buildings needs ceil(N / 2) PDFs — this answers open
# question 6 in docs/specs/lead-client-expansion.md.
#
# ## Other things worth knowing
#
# - Five subject-of-insurance rows per building (building, contents, business
#   income…), each with limit, coinsurance, valuation, cause of loss, inflation
#   guard, deductible amount and type, blanket number and forms/conditions.
#   The CRM records one building-level set, so it fills the first row.
# - Four blanket summary rows at the top (`CommercialProperty_Summary_*`),
#   which is where W4's Blanket model belongs.
# - `BuildingFireProtection_FireDistrictName_A/B` is where W4.2's fireDistrict
#   goes — per building on this form, one value on the Account.
# - The valuation and cause-of-loss fields are TEXT, not checkboxes. The
#   inventory gives field names, not the code vocabulary they expect, so the
#   mapping writes the human-readable label rather than an invented code — a
#   wrong code is a wrong value on a form an underwriter reads.
#
# Format: one field per line, as `listTemplateFields` returns it.
