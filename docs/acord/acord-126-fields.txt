# ACORD 126 (Commercial General Liability Section) — form field inventory
#
# Read off the agency's own uploaded template via the CRM's
# Settings → Form templates → Inspect fields, the same way
# acord-125-fields.txt and acord-140-fields.txt were.
#
# 257 fields. `src/lib/acordApp.test.ts` asserts every name the acord126
# branch of the mapping can emit against this list, so an invented field name
# fails a test instead of coming back as an "Unmatched fields" note after
# somebody has already sent the form.
#
# NOTE on the question codes. Two families of field appear below:
#
#   Contractors_Question_<XXX>Code_A
#   GeneralLiabilityLineOfBusiness_Question_<XXX>Code_A
#
# and they are NOT mappable from this list. The three-letter code is ACORD's
# own question identifier and nothing in the field name says which question it
# asks. Adjacency in this dump is not evidence either: AAB sits beside
# "ApplicantDrawPlansForOthers" in the Contractors family and beside
# "ApplicantActiveJointVentures" in the GeneralLiabilityLineOfBusiness one.
# A Y written into the wrong question box is a misstatement on a document an
# underwriter prices from, so the sub-contractor Yes/No answers the CRM holds
# are deliberately left to the AI gap-fill until the codes can be confirmed
# against the printed form.
